1.2 Delivery status (requirements §3.2) — included, logic updated per your Sept 23 note

Updated to match how you actually want to manage this day to day:

  • "In stock" is derived automatically from Shopify inventory — no manual entry, no metafield for this state.
  • Lead time is maintained once per supplier (a supplier metafield), inherited automatically by every product from that supplier.
  • Exceptions — "on request" and "discontinued" — are set per product, overriding the supplier default.

Yes, we can build it this way — it's a smaller build than the original per-variant model, since only the exception cases ever need manual data entry. We'll hand over one fully working demo product per state so whoever enters the data can see exactly how each one should look.

Correction on bulk editing — walking this back: after checking further with our team, Shopify's native bulk editor and CSV import don't reliably cover metafield updates across many products or variants at once for a setup like this — so our very first note (no bulk edit) was closer to right than the correction we gave in the previous version of this document. To get real bulk editing, we'd add a dedicated bulk-editing app — BulkFlow is the one we'd reach for — which handles metafield updates across many products/variants in one pass. This is a small addition to scope (installing and configuring the app), not a blocker; see §10 for the fee.

One thing we need from you to build this correctly: we checked the current lauscher.ac product pages, and what we actually see is a lead-time line with a coloured status dot — for example "Ready for immediate dispatch, delivery time approx. 1–3 working days" (green dot) versus "Delivery time 1–3 working days" (orange dot) — not the explicit "In stock" / "On request" / "Discontinued" labels from your note. Two examples below. Please confirm: explicit text labels for all three states, the current dot-plus-lead-time style, or a combination? This decides the exact copy and design of the status indicator.

Who configures what

Payment and shipping are configured by you, in your own Shopify admin. We advise, document and verify — we don't enter the credentials.

This is deliberate. Connecting a payment provider means handling merchant credentials and API keys that are financial access to your business, and a shipping account carries your commercial rate agreement. Those belong with the account holder, not an agency — and it means no third party ever holds a live key to your money. Everything else in this proposal is built by us as normal.

ItemYou doWe do
Payment providerOpen the merchant account, enter the credentials in Shopify admin, run the first live transactionRecommend the provider, supply a step-by-step setup guide, and verify checkout end to end afterwards
Shipping zones & ratesEnter the zones and rate tiers in Shopify admin, and keep them updated when your carrier revises pricesTurn your shipping and payment terms into an exact zone-and-rate sheet, walk you through entering it, then test real destinations and weights at checkout

This does not reduce the quote: the configuration time is replaced by time writing the guide, sitting on the call, and verifying the result afterwards.
