keywestspice.com speed and accessibility review

Page tested: https://www.keywestspice.com/ Test run: Nov 15, 2026 (PageSpeed Insights, Lighthouse 13.6.0) Report date: Nov 17, 2026 Prepared by: LitOS/LitGroup

Desktop is in good shape. The main problem is mobile performance (73/100), and almost all of that loss comes from one metric: the homepage banner takes 7.9 seconds to appear in Google's mobile test. Google's "good" threshold is 2.5 seconds.

The banner image itself is not large. It loads slowly because it shares the connection with many other files that start at the same time: product images that are bigger than they need to be, an oversized footer logo, and several widget and app scripts. We found 10 issues we can fix in the theme. Our quote for this work is in the Quote section.

Performance issues

Issues 1–7
1

Product images load too early

Low impact
Problem
Every product image in the homepage product list starts loading together with the banner. On mobile these cards sit below the first screen, so they only slow the banner down.
Fix
Load them when the visitor scrolls near them. We apply this to the homepage only, so collection pages keep showing their first row right away.
Result
Small once issue 2 is done, because the images will already be much lighter.
2

Product images are too large on mobile

High impact
Problem
The product list shows 2 cards per row on mobile, but the theme tells the phone that each image fills the whole screen. Phones download an 832 px image for a slot about 184 px wide.
Fix
Tell the browser the real slot width (half the screen).
Result
The 9 homepage product images drop from about 400 KB to about 75 KB on mobile.
3

Missing in-between image sizes

Medium impact
Problem
Product images are offered at 240, 352 and 832 px, with nothing in between. A product card about 400–450 px wide on desktop has to download the 832 px file.
Fix
Add 416 px and 600 px versions so each slot gets a close match.
Result
Mostly helps desktop, where Google's report flags about 1.5 MB of oversized images.
4

Footer logo downloads far too large

Medium impact
Problem
The footer logo shows at about 100 px wide, but desktop downloads a 1,600 px version (138 KB) and mobile an 832 px version (113 KB). It also loads right away, even though it sits at the bottom of the page.
Fix
Request the size that is actually shown, and load it when the visitor scrolls near the footer.
Result
About 105 KB less on mobile.
5

Extra jQuery file blocks the page from showing

Medium impact
Problem
A copy of the jQuery library loads from an outside server before anything can appear on screen, holding the page back about 1.2 s on mobile. Nothing in the theme uses it, and the Wholesale Gorilla scripts bring their own copy. Right now jQuery downloads 4 times on every page.
Fix
Remove this copy, or let it load without blocking the page.
Result
The page no longer waits for this file before it starts showing.
Testing
This line was added by the Wholesale Gorilla app. After the change we test wholesale sign-up, wholesale login and the cart. If a future app update adds the line back, it will need to be removed again.
6

Google Merchant badge loads about 290 KB of script on every page

High impactNeeds your decision
Problem
The Google Merchant badge in the bottom-left corner pulls about 290 KB of Google scripts at the start of every page load, and about 165 KB of that goes unused. It is the largest single item we can change in the theme. The badge also adds a frame without a title, which screen readers can't describe. This is an accessibility error on both mobile and desktop.
Fix
Load the badge when the visitor first interacts with the page (scroll, tap, mouse move or key press), and give its frame a title.
Trade-off
The badge appears a moment after the visitor starts scrolling instead of on page load. Google's test doesn't scroll or tap, so the badge isn't loaded during the test. Real visitors get the same faster first load and see the badge as soon as they start browsing.
Result
The largest single cut in what loads with the banner, less work for the phone during page load, and the frame-title error fixed on mobile and desktop.

Your decision: is it OK for the Google Merchant badge to appear after the visitor starts interacting with the page?

7

Product card font is missing

Low impactNeeds a file from you
Problem
The font used for product names and prices on cards (Sqmarket) returns "file not found". Cards currently show a fallback font, so they don't match the design.
Fix
Upload the font files into the theme.
Result
Cards show the intended font again, so card text will look slightly different from today.

Please send: the original Sqmarket font files (.woff2 or .woff, regular and medium) and confirm the license covers web use.

Accessibility issues

Issues 8–10
8

Crossed-out prices are hard to read

Medium impact
Problem
The original price shown next to a sale price is set to 40% opacity. Its contrast is about 2.3:1, while the accessibility standard (WCAG AA) asks for 4.5:1.
Fix
Raise it to about 70% opacity (about 5:1). It stays visibly lighter than the sale price.
Result
Fixes the contrast error on mobile and desktop.
9

Banner headline uses the wrong heading level

Low impact
Problem
The banner headline "Spice Wholesaler in Key West, FL…" is coded as a level-6 heading, the smallest level, right after the page's main heading. Screen reader users move through a page by heading level, so the skip is confusing.
Fix
Change it to a level-2 heading and keep its current look.
Result
Fixes the heading-order error. This headline carries your main keywords, so a proper heading level also helps search engines read the page.
10

Desktop menu list structure

Medium impact
Problem
The desktop menu items (Shop, eGift Card, Wholesale and the "More" button) are marked up in a way that breaks the list structure screen readers expect.
Fix
Correct the markup on the menu items and the "More" button, then re-run the test to confirm.
Result
Fixes the list-structure error on desktop. Mobile is not affected.

Photo compression

The mobile banner photo can be about 63 KB smaller with better compression. This is the image Google measures, so a lighter file helps the banner appear sooner. Several gift box photos can also be 25–66 KB smaller each.

We re-compress these photos and re-upload them. If you have the original files, they give a better result than the current uploads.

Google's report also lists items we don't recommend acting on: files and scripts managed by Shopify itself (combined stylesheet, Shop login, analytics), security header suggestions that Shopify sets on its servers, and cache settings that each app controls on its own files.

Also noticed

Some product cards show crossed-out price ranges such as "$0.00 – $144.00" and "$144.00 – $144.00". This happens because a compare-at price is set on only some variants of those products. It doesn't affect speed, but shoppers can see it. We suggest reviewing the compare-at prices on those products.
